From a moving depth sensor to a room map that stays.

Context
MadHacks, November 2026
Team
Ryan, Charvik, Akshath, Rishi
My focus
Viewer integration and room analysis

How the team’s system fits together

  1. CaptureiPhone LiDAR and motion data
  2. MapMac mapper accumulates geometry
  3. ReviewBrowser analysis and floor-plan exports

Built at MadHacks with Charvik, Akshath, and Rishi. The team repository is named EchoSense. The prototype brings phone depth scans into a browser where the map can be inspected, classified, saved, and exported as a floor plan.

My contribution

  • Connected the Mac mapper's output to the browser's room-analysis workflow.
  • Built persistent spatial memory and geometric room-classification logic.
  • Worked on floor-plan and PNG exports, saved-map behavior, and audio cues.
  • Added the HC-SR04 firmware and sonar-versus-LiDAR cross-check, with wiring and mounting guidance.

A design choice: preserve what is unknown

The spatial-memory and floor-plan work keeps observations after the scanner moves away. Areas without measurements remain unobserved. Geometric rules can classify a tall cabinet as a wall, so the output needs interpretation.

Mapper integrationFloor-plan implementation

The team has recorded real-phone mapper runs. The featured image comes from the final November 15 scans; its colors indicate height, and the orange line shows the phone path. Lighting conditions were not recorded. Full-darkness performance and combined real-phone/sonar operation remain unverified. This is a hackathon prototype for simulated search-and-rescue planning.

PROJECT NOTES

ALGOGEM

Strategy in a sealed-bid gem auction.

I built a Python bot using the competition’s provided client. Each turn involves decisions about bidding and which card to reveal. The shared display changes the value of the gems players hold.

How the bot works

  • Records the gems each player wins after every auction.
  • Compares my collection with the strongest rival’s holdings to score reveal choices.
  • Accounts for saturation when a color already has five cards in the display.
  • Uses fixed bidding thresholds with balance limits and rules for different auction types.

The program provided the game, client interface, and starter template. My repository preserves the bot and adds a standalone strategy example. The strategy uses heuristics rather than expected-value calculations or learned predictions.

Global Flu Tracker

Second overall at HackAppleton, 2025.

A three-person project by Ryan Lai, Akshath, and Michael. I worked on the interactive Leaflet map, toggleable case layers, location lookup, and distance-based proximity scoring.

What the project demonstrates

  • Leaflet maps using OpenStreetMap tiles.
  • Separate human and animal outbreak layers.
  • Nominatim geocoding for place searches.
  • Haversine distance calculations for proximity scores.

The linked portfolio fork preserves the original authorship and license. It now includes a later C++17 backend. My contribution described here is to the original browser project. The fixed dataset and scripted simulation are a hackathon demonstration, not a live surveillance feed or validated forecast.
